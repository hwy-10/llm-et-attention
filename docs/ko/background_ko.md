## 1. 프로젝트 개요

### 1.1 무엇을 만드는가

대규모 언어 모델(LLM)이 문장을 한 글자씩 생성할 때 반복 수행하는 **어텐션 점수 계산**을 전담하는 디지털 하드웨어를 설계합니다.

이 하드웨어의 특징은 계산을 **상위 비트부터 순차적으로** 수행한다는 점입니다. 계산이 진행되는 도중에 "이 단어는 아무리 더 계산해도 중요한 후보가 될 수 없다"는 것이 수학적으로 확정되면, 남은 하위 비트를 **읽지도 계산하지도 않고** 그 단어의 처리를 중단합니다. 이 동작을 조기 종단(early termination)이라고 부릅니다.

설계는 전 과정을 Verilog/SystemVerilog RTL로 기술하고 FPGA에 구현하여 검증합니다.

### 1.2 왜 만드는가

LLM 추론의 병목은 연산 속도가 아니라 메모리 접근입니다. 답변을 생성하는 동안 이전 단어들의 정보를 매번 전부 읽어와야 하는데, 읽어온 데이터는 한 번 쓰이고 버려집니다. 즉 데이터를 옮기는 데 대부분의 시간과 에너지가 소모됩니다.

그런데 어텐션 계산의 결과를 보면, 읽어온 데이터의 대부분은 최종 출력에 거의 영향을 주지 않습니다. 극소수의 단어만 의미 있는 비중을 차지하고 나머지는 사실상 버려집니다. **버려질 데이터를 끝까지 읽고 계산하는 것이 낭비의 본질**이며, 이를 계산 도중에 판별해 중단하자는 것이 본 설계의 출발점입니다.

### 1.3 설계 범위

| 구분 | 내용 |
|---|---|
| 대상 연산 | 어텐션 점수 계산 (Q·Kᵀ) |
| 대상 단계 | 디코딩(Decode) 단계 |
| 데이터 형식 | INT8 정수 |
| 구현 수단 | RTL 설계 및 FPGA 구현 |
| 검증 기준 모델 | Llama 3.2 1B (계층 16, KV 헤드 8, 헤드 차원 64) |

다음은 본 프로젝트의 범위에 포함하지 않습니다.

- Softmax 및 Value 행렬 곱(S·V) 하드웨어 — 여유가 있을 경우 확장 과제로 검토
- 모델 전체의 하드웨어 실행 — 단일 계층·단일 헤드 수준에서 측정하고 나머지는 해석적으로 추정
- 반도체 칩 제작(테이프아웃)

## 2. 왜 메모리가 문제인가

### 2.1 연산보다 데이터 이동이 비싸다

반도체에서 에너지가 어디에 쓰이는지를 보면 직관과 다른 결과가 나옵니다. 표 2.1은 45nm 공정을 기준으로 각 동작에 드는 에너지를 비교한 것으로, Horowitz(ISSCC 2014)가 정리한 널리 인용되는 자료입니다.

**표 2.1 동작별 에너지 비교 (45nm 기준)**

| 동작 | 에너지 | 32비트 정수 덧셈 대비 |
|---|---|---|
| 32비트 정수 덧셈 | 0.1 pJ | 1배 |
| 32비트 부동소수 덧셈 | 0.9 pJ | 9배 |
| 32비트 곱셈 | 3.1 pJ | 31배 |
| 8KB SRAM에서 32비트 읽기 | 5 pJ | 50배 |
| DRAM에서 32비트 읽기 | 640 pJ | 6,400배 |

덧셈 한 번을 수행하는 비용보다, 그 덧셈에 사용할 숫자를 DRAM에서 가져오는 비용이 약 6,400배 큽니다. 즉 **계산은 저렴하고 데이터 운반은 비쌉니다.**

### 2.2 메모리 월

이런 격차가 생긴 이유는 공정 미세화의 효과가 소자와 배선에 균등하게 적용되지 않았기 때문입니다. 트랜지스터는 세대가 바뀔 때마다 작아지고 빨라졌지만, 배선은 얇아지면서 저항이 오히려 커졌습니다. 그 결과 연산 성능과 메모리 대역폭의 격차가 계속 벌어졌고, 이 현상을 **메모리 월(memory wall)** 이라고 부릅니다.

메모리 월에 대한 접근법은 크게 두 가지입니다. 하나는 메모리를 연산기 가까이 옮기는 것(HBM, 3D 적층)이고, 다른 하나는 **애초에 옮기는 데이터의 양을 줄이는 것**입니다. 본 프로젝트는 후자에 해당합니다.

## 3. LLM을 하드웨어 관점에서 보기

### 3.1 어텐션 연산

LLM의 중심 연산은 다음 한 줄로 표현됩니다.

```
Attention(Q, K, V) = softmax( Q · K^T / sqrt(d) ) · V
```

세 개의 행렬이 등장합니다.

| 기호 | 이름 | 역할 |
|---|---|---|
| Q | Query | 현재 처리 중인 단어가 "무엇을 찾고 있는지" |
| K | Key | 각 단어가 가진 "색인 정보" |
| V | Value | 각 단어가 담고 있는 "실제 내용" |

연산은 세 단계로 진행됩니다.

1. `Q · K^T` — 현재 단어와 이전 단어들 사이의 관련도를 점수로 계산합니다.
2. `softmax` — 점수들을 합이 1인 비율로 변환합니다.
3. `· V` — 그 비율에 따라 각 단어의 내용을 가중 평균합니다.

도서관에서 질문에 답하는 과정에 비유할 수 있습니다. 모든 책의 색인(K)을 훑어 내 질문(Q)과의 관련도를 매기고, 그 점수를 비율로 환산한 뒤, 점수가 높은 책의 내용(V)을 많이 반영해 답을 구성하는 것입니다.

본 프로젝트가 다루는 부분은 **1단계인 점수 계산 `Q · K^T`** 입니다.

### 3.2 두 단계: Prefill과 Decode

LLM 추론은 성격이 전혀 다른 두 단계로 나뉩니다. 이 구분이 본 프로젝트에서 가장 중요한 전제이므로 정확히 이해할 필요가 있습니다.

**Prefill 단계** — 사용자가 입력한 프롬프트 전체를 한 번에 처리합니다. 예를 들어 1,000개 단어짜리 입력이라면 1,000개 단어의 K, V를 모두 계산해 저장하고, 동시에 1,000×1,000 규모의 어텐션을 계산합니다. 연산량이 매우 크지만 병렬화가 잘 되므로 GPU가 잘 처리하는 작업입니다. 이런 상태를 연산 병목(compute-bound)이라고 합니다.

**Decode 단계** — 답변을 한 단어씩 순차적으로 생성합니다. 매 단계마다 새 단어 하나의 K, V를 계산해 저장하고(쓰기 1건), 저장되어 있는 이전 단어들의 K, V를 전부 읽어(읽기 N건) 어텐션을 계산합니다. 연산량은 작지만 읽어야 할 데이터가 많아, 메모리 대역폭이 성능을 결정합니다. 이를 메모리 병목(memory-bound)이라고 합니다.

```
   Prefill                        Decode
   ------------------------       ------------------------
   입력 1,000단어 일괄 처리        답변 1단어씩 생성

   K,V 계산 및 저장 1,000건        K,V 저장 1건
   어텐션 1,000 x 1,000            어텐션 1 x N

   연산 병목                       메모리 병목
   GPU가 잘 처리                   <-- 본 프로젝트 대상
```

**그림 3.1 Prefill과 Decode의 차이**

한 번의 Decode 단계에서 쓰기는 1건, 읽기는 N건입니다. N이 1,000이라면 비율이 1:1,000입니다. 즉 Decode는 사실상 읽기만 수행하는 작업입니다.

### 3.3 KV 캐시

Decode 단계에서 t번째 단어를 생성하려면 1번부터 t−1번까지 이전 단어들의 K와 V가 모두 필요합니다. 매번 다시 계산하면 연산량이 t의 제곱에 비례해 증가하므로, 한 번 계산한 K와 V를 저장해두고 재사용합니다. 이 저장 공간을 **KV 캐시(KV cache)** 라고 합니다.

KV 캐시는 연산량 문제를 해결했지만 대신 새로운 문제를 만들었습니다. 매 단계마다 캐시 전체를 읽어야 하고, 문장이 길어질수록 캐시가 계속 커집니다. Decode 단계의 메모리 병목은 여기서 발생합니다.

여기서 한 가지 중요한 사실을 짚고 넘어갈 필요가 있습니다. 문헌에서 "어텐션은 가중치가 매번 바뀌므로 메모리 중심 가속기에 적합하지 않다"는 서술을 종종 볼 수 있는데, 이는 Prefill 단계에 해당하는 설명입니다. Decode 단계에서 t번째 단어의 K는 t단계에 한 번 저장된 뒤 t+1, t+2, … 이후 모든 단계에서 읽힙니다. 전체 길이가 T일 때 평균 재사용 횟수는 약 T/2이며, T가 2,048이면 한 번 쓰고 약 1,000번 읽는 셈입니다. 저장 비용은 충분히 상쇄됩니다.

### 3.4 연산 강도로 본 병목

Decode가 메모리 병목이라는 것을 숫자로 확인해 보겠습니다. **연산 강도(arithmetic intensity)** 는 메모리에서 1바이트를 읽을 때 몇 번의 연산을 수행하는지를 나타내는 지표입니다.

Decode 한 단계에서 읽는 데이터와 수행하는 연산은 다음과 같습니다.

```
   읽는 데이터 : K와 V 전체 = 2 x N x d 개 원소 x 2 byte(FP16) = 4Nd bytes
   수행 연산   : Q·K^T (Nd회 MAC) + S·V (Nd회 MAC) = 4Nd FLOPs

   연산 강도 = 4Nd FLOPs / 4Nd bytes = 1 FLOP/byte
```

1바이트를 읽어서 연산을 한 번 하고 버리는 셈입니다. 이제 이 값을 GPU가 요구하는 수준과 비교합니다. NVIDIA A100의 FP16 연산 성능은 312 TFLOPS, HBM 대역폭은 약 2.0 TB/s입니다.

```
   연산 유닛을 100% 활용하는 데 필요한 연산 강도
     = 312 TFLOPS / 2.0 TB/s
     = 약 156 FLOP/byte
```

필요한 값이 156인데 실제 값이 1입니다. 다시 말해 GPU의 연산 유닛은 1%에도 못 미치는 비율로만 사용되고, 나머지 시간은 데이터를 기다립니다. 더 빠른 연산기를 붙여도 상황은 개선되지 않습니다. **줄여야 할 것은 연산이 아니라 메모리 접근량입니다.**

### 3.5 KV 캐시의 크기

KV 캐시가 실제로 얼마나 큰지 확인해 봅니다. 1.3절에서 정한 대상 모델인 Llama 3.2 1B는 계층 16개, KV 헤드 8개, 헤드 차원 64를 사용합니다.

```
   단어 1개가 만드는 KV 데이터
     = 2(K와 V) x 16(계층) x 8(헤드) x 64(차원) x 2 byte(FP16)
     = 32,768 byte
     = 32 KB

   단어 512개  ->  32 KB x 512 = 16 MB
```

일반적인 온칩 SRAM 매크로의 용량이 수십에서 수백 KB인 것과 비교하면 두 자릿수 이상 차이가 납니다. KV 캐시 전체를 칩 안에 두는 것은 불가능하며, 외부 메모리와 주고받는 트래픽을 줄이는 것이 현실적인 접근입니다.

## 4. 어텐션의 두 가지 성질

본 설계는 어텐션 연산이 가진 두 가지 성질을 이용합니다. 두 성질 모두 실험적으로 잘 알려져 있으며, 여러 하드웨어 가속기 연구가 이를 근거로 삼고 있습니다.

### 4.1 점수 분포는 매우 치우쳐 있다

어텐션 점수에 softmax를 적용하면, 지수 함수의 성질 때문에 큰 값은 크게 증폭되고 작은 값은 급격히 억제됩니다. 단어 8개에 대한 예를 보겠습니다.

```
   원 점수      :   1.2    0.8    9.5    1.0    0.5    8.8    0.9    1.1

   exp 적용     :   3.3    2.2  13360    2.7    1.6   6634    2.5    3.0

   softmax (%)  : 0.017  0.011  66.77  0.014  0.008  33.16  0.012  0.015
                                -----                -----
                                    합계 99.93%
```

**그림 4.1 어텐션 점수의 softmax 변환**

점수 9.5와 8.8을 가진 두 단어가 전체 비중의 99.9%를 차지하고, 나머지 여섯 단어는 모두 합쳐도 0.1%에 미치지 못합니다. 점수 차이는 최대 9배에 불과했지만 지수 함수를 거치면서 비중 차이는 수천 배로 벌어집니다. 실제 모델에서도 이런 편중은 일반적으로 관찰되며, 문장이 길어질수록 더 뚜렷해집니다.

이 성질이 의미하는 바는 다음과 같습니다. 같은 크기의 오차라도 어디에서 발생하느냐에 따라 결과에 미치는 영향이 완전히 다릅니다.

- 점수가 낮은 단어에서 발생한 오차: softmax가 억제하므로 출력에 거의 영향이 없음
- 점수가 높은 단어에서 발생한 오차: exp로 증폭되므로 출력이 눈에 띄게 달라짐

따라서 **점수가 높은 소수의 단어만 정확히 계산하면 되고, 나머지는 정확할 필요가 없습니다.** 더 나아가, 상위권에 들지 못할 것이 확실하다면 아예 계산하지 않아도 됩니다.

### 4.2 비트마다 중요도가 다르다

두 번째 성질은 정수 표현 자체의 성질입니다. 8비트 이진수 `10110101`을 봅니다.

```
   비트 위치 :  b7    b6    b5    b4  |  b3    b2    b1    b0
   가중치    : 128    64    32    16  |   8     4     2     1
```

최상위 비트(b7)가 틀리면 값이 128만큼 어긋나지만, 최하위 비트(b0)가 틀리면 1만큼 어긋납니다. **비트는 서로 대등하지 않으며, 상위 비트가 값을 사실상 결정합니다.**

이를 계산 순서에 적용하면, 상위 비트부터 계산할 경우 몇 개의 비트만 처리해도 결과의 대략적인 크기를 파악할 수 있습니다. 이런 방식을 **MSB 우선(MSB-first) 계산**이라고 합니다.

### 4.3 두 성질을 합치면

두 성질을 결합하면 다음과 같은 전략이 도출됩니다.

> 어텐션 점수를 상위 비트부터 계산한다. 몇 개의 비트만 처리한 시점에서 "이 단어는 아무리 더 계산해도 상위권에 들 수 없다"는 판단이 가능하다면, 나머지 비트는 읽지도 계산하지도 않는다.

여기서 핵심은 이 판단이 **추측이 아니라 수학적으로 확정될 수 있다**는 점입니다. 이 부분을 5장에서 다룹니다.

## 5. 제안 기법: 상위 비트 우선 계산과 조기 종단

### 5.1 기본 아이디어

어텐션 점수 계산을 다음 순서로 수행합니다.

```
   1. KV 캐시를 비트 자리별로 나누어 저장한다
   2. 최상위 자리부터 한 자리씩 읽어 부분 점수를 누적한다
   3. 매 자리마다, 남은 자리들이 최대로 기여할 수 있는 값을 계산한다
   4. "현재 부분 점수 + 남은 최대 기여"가 기준값에 못 미치면 그 단어를 중단한다
   5. 중단된 단어의 남은 자리는 읽지 않는다
```

5번이 핵심입니다. 연산을 건너뛰는 데 그치지 않고 **메모리 읽기 자체를 건너뛰기 때문에**, 3장에서 확인한 메모리 병목을 직접 줄일 수 있습니다.

### 5.2 비트평면 저장

상위 비트만 따로 읽으려면 저장 방식을 바꿔야 합니다. 일반적으로는 한 단어의 8비트를 한 덩어리로 저장하지만, 본 설계에서는 **같은 자리수끼리 모아서** 저장합니다. 이렇게 모은 단위를 비트평면(bit-plane)이라고 부릅니다.

```
   [일반적인 저장 방식]
     K1 = 1 0 1 1 0 1 0 1      <- 단어 1의 8비트가 한 덩어리
     K2 = 0 1 1 0 1 1 0 0
     K3 = 1 1 0 0 1 0 1 0

   [비트평면 저장 방식]
     평면 b7 : 1  0  1  ...     <- 모든 단어의 b7 비트만 모음
     평면 b6 : 0  1  1  ...
     평면 b5 : 1  1  0  ...
        :
     평면 b0 : 1  0  0  ...
```

**그림 5.1 비트평면 저장**

이렇게 저장하면 "평면 b7만 읽기"가 하나의 연속된 메모리 접근이 되어, 상위 자리만 선택적으로 읽는 것이 물리적으로 가능해집니다.

한 가지 유의할 점은 쓰기 경로입니다. 새 단어의 K 값 하나를 저장하려면 8개 비트를 8개 평면에 각각 나누어 써야 하므로, 일반적인 저장 방식보다 쓰기가 복잡해집니다. 다만 3.2절에서 확인했듯이 Decode 단계에서 쓰기는 단계당 1건, 읽기는 N건이므로 쓰기 비용의 비중은 작습니다. 구현 시에는 여러 단어를 모았다가 한 번에 쓰는 방식이나, 쓰기 시점에 비트를 재배열하는 소규모 버퍼를 두는 방식을 검토할 수 있습니다.

### 5.3 상위 비트부터 누산하기

단어 j에 대한 어텐션 점수를 비트평면 단위로 전개하면 다음과 같습니다.

```
   s_j = SUM over b=0..7 of  2^b * ( q · K_j^(b) )
```

여기서 `K_j^(b)`는 단어 j의 K 벡터에서 b번째 비트만 모은 0/1 벡터입니다. `q · K_j^(b)`는 K의 해당 비트가 1인 위치의 q 값만 골라서 더한 값이므로, **곱셈기 없이 조건부 덧셈만으로 계산됩니다.** 이 값을 부분 내적 `P_b`라고 부르겠습니다.

```
   P_b = SUM over i of  q_i * K_ji^(b)
       = ( K의 b번째 비트가 1인 위치의 q 값들의 합 )
```

여기서 K의 각 원소는 부호 없는 8비트 정수로 표현한다고 가정합니다. 즉 실제 값에서 기준점(zero-point)을 빼서 0~255 범위로 옮긴 뒤 저장하고, 최종 점수에서 기준점에 의한 보정항을 한 번에 더해 주는 방식입니다. 이런 비대칭 양자화는 KV 캐시를 저정밀도로 저장하는 연구에서 표준적으로 쓰이는 방법입니다([11] 참조). 반면 q는 부호가 있는 정수 그대로 사용합니다.

> **부호 없는 표현을 쓰는 이유 — 필연이 아니라 회로 단순화입니다**
>
> 부호 없이 저장하면 비트 자리값이 `[128, 64, ..., 1]` 로 **전부 양수**가 되어, 5.4절의 상한식이 8개 평면 전부에 **하나의 공식**으로 그대로 적용됩니다.
>
> 예전에는 "부호 있는(2의 보수) 표현을 쓰면 최상위 비트의 자리값이 −128이라 상한식이 깨진다"고 설명했으나, **이는 사실이 아닙니다.** 상위 비트부터 처리하므로 부호 비트는 첫 라운드에 이미 확정되어 '결정된 부분합'에 들어가고, 아직 읽지 않은 비트들의 자리값은 전부 양수입니다. 따라서 부호 있는 표현에서도 유효한 상한을 세울 수 있습니다.
>
> **다만 첫 평면(아직 아무것도 읽지 않은 시점)은 예외입니다.** 부호 있는 표현에서는 그 시점의 상한이 `−128·Q− + 127·Q+` 라는 **다른 식**이 됩니다. 부호 없는 표현의 식(`255·Q+`)을 그대로 쓰면, 음수 q의 합이 양수보다 큰 경우 상한이 참값보다 작아져 깨집니다. 두 번째 평면부터는 남은 자리값이 전부 양수라 같은 형태가 됩니다.
>
> 부호 없는 표현을 택하는 진짜 이유는 **바로 이 첫 평면의 예외 처리가 사라져 8개 평면에 하나의 식을 그대로 쓸 수 있기 때문**입니다. 발표에서 "수학적으로 필연"이라고 말하면 안 됩니다.

상위 m개 평면(b = 7부터 8−m까지)을 처리한 시점에서 확정된 부분 점수는 다음과 같습니다.

```
   S_m = SUM over b=8-m..7 of  2^b * P_b
```

### 5.4 잔여 상한과 종단 조건

아직 읽지 않은 하위 평면들이 앞으로 **최대한 기여할 수 있는 값**은 정확히 계산할 수 있습니다. 남은 비트가 모두 1이고, 그 위치의 q가 모두 양수인 경우가 최대입니다.

```
   Q+ = q 원소 중 양수인 것들의 합

   R_m = SUM over b=0..7-m of  2^b * Q+
       = ( 2^(8-m) - 1 ) * Q+
```

`Q+`는 q에만 의존하는데, q는 한 번의 디코딩 단계 안에서 모든 단어에 대해 동일합니다. 따라서 **단계당 한 번만 계산해 레지스터에 넣어 두면 됩니다.**

이후 매 평면의 `R_m`은 곱셈기 없이 구해집니다. `2^(8-m) - 1` 이 `2^n - 1` 꼴이므로 시프트와 뺄셈으로 대체되기 때문입니다.

```
   ( 2^(8-m) - 1 ) * Q+   =   ( Q+ << (8-m) )  -  Q+
```

배럴 시프터 하나와 뺄셈기 하나면 충분합니다.

이제 상한이 정해집니다.

```
   s_j  <=  S_m + R_m
```

기준값을 θ(현재까지 확보한 상위 k번째 점수)라고 하면, 종단 조건은 다음과 같습니다.

```
   -------------------------------------------------
     S_m + R_m  <  θ    ->   단어 j 처리 중단
   -------------------------------------------------
```

이 부등식이 성립하면 남은 비트를 모두 읽어도 s_j는 θ를 넘을 수 없습니다. 따라서 **상위 k개 집합에서 이 단어가 누락될 가능성은 없습니다.** 근사가 아니라 손실 없는(exact) 판정입니다.

### θ는 어디서 오는가

여기서 한 가지 문제가 남습니다. θ를 "지금까지 계산이 끝난 단어들의 상위 k번째 점수"로 정의하면, 계산이 완전히 끝난 단어가 하나도 없는 초반에는 θ를 정할 수 없습니다. 특히 모든 단어를 평면 단위로 나란히 진행시키는 방식에서는 8개 평면을 전부 처리하기 전까지 확정된 점수가 하나도 없으므로, **종단이 단 한 번도 일어나지 않습니다.**

해결책은 상한과 짝을 이루는 **하한**을 함께 계산하는 것입니다. 남은 비트가 모두 0이고 그 위치의 q가 모두 음수인 경우가 최소값이므로, 다음과 같이 하한이 정해집니다.

```
   Q- = q 원소 중 음수인 것들의 합   (0 이하)

   L_m = S_m + ( 2^(8-m) - 1 ) * Q-

   따라서    L_m  <=  s_j  <=  S_m + R_m
```

이제 θ를 **활성 단어들의 하한 중 k번째로 큰 값**으로 정합니다. 그러면 다음 논리가 성립합니다.

> 하한이 θ 이상인 단어가 최소 k개 있고, 그 단어들의 실제 점수는 각자의 하한 이상이므로 θ 이상이다.
> 따라서 상한이 θ보다 작은 단어는 상위 k에 들 수 없다.

손실 없는 판정이 그대로 유지되면서, **평면을 한두 개만 처리한 시점부터 종단이 동작합니다.** 상한과 하한을 함께 좁혀 가며 후보를 제거하는 이 방식은 최적화 문제에서 널리 쓰이는 분기 한정(branch and bound) 기법과 같은 구조입니다.

### 5.5 수치 예제

이해를 돕기 위해 차원을 4로 줄이고, **단어 하나가 종단되는 과정만** 따라가 보겠습니다.

```
   q  = [ 50, -30, 20, -10 ]
   Q+ = 50 + 20 = 70
   θ  = 3000
```

여기서 θ는 **다른 단어들의 하한에서 이미 정해진 기준값**입니다(직전 절 참조). 이 예제는 단어 하나만 따라가므로 θ가 어떻게 만들어지는지는 보이지 않고, 그 값이 주어졌을 때 **이 단어가 언제 잘려 나가는지**만 봅니다.

**평면 2개 처리 후 (b7, b6)**

```
   P_7 = 20,  P_6 = -10  이라고 하면

   S_2 = 128 * 20 + 64 * (-10) = 2560 - 640 = 1920
   R_2 = (2^6 - 1) * 70 = 63 * 70 = 4410

   S_2 + R_2 = 6330  >  3000     ->  계속 진행
```

**평면 4개 처리 후 (b7 ~ b4)**

```
   P_5 = -30,  P_4 = 0  이라고 하면

   S_4 = 1920 + 32 * (-30) + 16 * 0 = 1920 - 960 = 960
   R_4 = (2^4 - 1) * 70 = 15 * 70 = 1050

   S_4 + R_4 = 2010  <  3000     ->  종단
```

이 단어는 나머지 4개 평면을 읽지 않습니다. 메모리 읽기와 연산이 각각 절반으로 줄어들며, 결과의 정확성에는 아무런 영향이 없습니다.

### 5.6 정확 모드와 근사 모드

θ를 어떻게 설정하느냐에 따라 두 가지 모드로 동작할 수 있습니다.

**표 5.1 두 가지 동작 모드**

| 모드 | θ 설정 | 정확도 | 절감 |
|---|---|---|---|
| 정확(exact) | 실제 상위 k번째 점수를 그대로 사용 | 손실 없음 | 보수적 |
| 근사(approx) | 실제 값보다 높게 설정 (여유값 margin을 더함) | 일부 손실 발생 | 공격적 |

정확 모드는 5.4절의 부등식을 그대로 사용하므로 결과가 원래 계산과 완전히 동일합니다.

근사 모드는 θ를 실제 값보다 높게 잡습니다. θ가 높아지면 `S_m + R_m < θ` 조건을 만족하는 단어가 늘어나므로 더 많은 단어가 일찍 중단됩니다. 다만 이 경우 상한이 θ를 넘지 못한다는 보장이 사라지므로, 실제로는 상위 k에 들어야 할 단어가 잘려 나갈 수 있습니다. 4.1절에서 본 것처럼 대부분의 단어는 비중이 극히 작으므로 몇 개가 바뀌어도 최종 출력에는 큰 영향이 없지만, 그 허용 범위를 실험으로 확인해야 합니다.

여유값을 조금씩 바꾸어 가며 측정하면 **절감량과 정확도 사이의 관계 곡선**을 얻을 수 있고, 이것이 본 프로젝트의 주요 결과물이 됩니다.

### 5.7 무엇이 절약되는가

조기 종단으로 줄어드는 항목은 두 가지입니다.

```
   1. 연산 사이클    : 처리하지 않은 평면 수만큼 감소
   2. 메모리 읽기    : 읽지 않은 평면만큼 감소   <-- 더 중요
```

3장에서 확인했듯이 Decode 단계는 메모리 병목이므로, 두 번째 항목이 성능에 직접적인 영향을 줍니다. 연산만 줄이는 기법이 이 단계에서 효과가 제한적인 것과 대비되는 지점입니다.

> **정직하게 짚어야 할 두 가지**
>
> **① 기준 설계(①)보다 사이클은 오히려 많습니다.** 비트평면을 한 장씩 처리하므로 한 단어에 8사이클을 씁니다. 512단어 기준으로 기준 설계 4,305 사이클 대비 제안 설계는 34,440 사이클입니다. 조기 종단으로 줄여도 이 구조적 차이는 남습니다.
>
> **제안의 근거는 사이클이 아니라 (a) DSP 미사용 (b) 메모리 읽기 감소입니다.** 발표에서 "빨라진다"고 말하면 안 됩니다.
>
> **② 읽지 않은 평면이 곧 절감이 되지는 않습니다.** 메모리는 여러 단어를 한 워드에 묶어 저장하므로, **워드 안에 살아 있는 단어가 하나라도 있으면 워드 전체를 읽어야 합니다.** 종단된 단어가 흩어져 있으면 이론적 절감이 실현되지 않습니다. 6.3-(2)의 '작업 압축'이 필요한 진짜 이유가 이것입니다.

## 6. 하드웨어 구조

### 6.1 전체 구성

```
   +----------------------------------------------------------+
   |  KV 캐시 메모리 (BRAM) - 비트평면 정렬                     |
   |    [평면 b7][평면 b6][평면 b5] ... [평면 b0]               |
   +--------------------------+-------------------------------+
                              |  평면 단위 순차 읽기
                              |  (중단된 단어는 읽지 않음)
                              v
   +----------------------------------------------------------+
   |  부분 내적 유닛 (Masked-Sum Unit)                          |
   |    K의 비트가 1인 위치의 q 값만 골라 가산 트리로 합산       |
   |    곱셈기 불필요 - 조건부 덧셈만 수행                       |
   +--------------------------+-------------------------------+
                              v
   +----------------------------------------------------------+
   |  시프트 누산기 (Shift & Accumulate)                        |
   |    부분 내적에 2^b 가중치를 적용해 누적                     |
   +--------------------------+-------------------------------+
                              v
   +----------------------------------------------------------+
   |  조기 종단 제어기 (Early Termination Controller)           |
   |    Q+ 레지스터, 잔여 상한 R_m 계산, 종단 판정               |
   |    단어별 진행 상태 관리                                    |
   +---+----------------------+-------------------------------+
       ^                      |
       |  θ 되먹임             v
       |          +----------------------------------------+
       +----------+  기준값 관리부 (Threshold / Top-k)      |
                  |    확정된 점수로 θ 갱신                  |
                  +----------------------------------------+

   ※ 중단 신호는 KV 캐시 메모리의 읽기 요청도 함께 차단한다
```

**그림 6.1 전체 블록 구성**

### 6.2 블록별 기능

**KV 캐시 메모리** — 비트평면 순서로 정렬된 BRAM입니다. 주소 생성기가 평면 번호와 단어 범위를 받아 해당 구간만 읽습니다. 중단된 단어에 대해서는 읽기 요청 자체가 발생하지 않아야 절감 효과가 실현됩니다.

**부분 내적 유닛** — 읽어온 비트평면과 q 벡터를 받아 `P_b`를 계산합니다. 각 비트가 1인 위치의 q 값만 통과시키는 마스킹 논리와, 그 결과를 합산하는 가산 트리로 구성됩니다. 곱셈이 필요 없으므로 DSP 블록을 사용하지 않고 LUT만으로 구현할 수 있습니다.

**시프트 누산기** — `P_b`에 자리수 가중치 `2^b`를 적용해 누적합니다. 시프트는 배선으로 처리되므로 추가 비용이 거의 없습니다.

**조기 종단 제어기** — 본 설계의 핵심 블록입니다. 단계 시작 시 `Q+`를 한 번 계산해 레지스터에 보관하고, 매 평면마다 `R_m`을 갱신한 뒤 종단 조건을 판정합니다. 판정 결과는 단어별 상태 비트로 관리되어 메모리 읽기 요청과 연산 파이프라인을 제어합니다.

**기준값 관리부** — θ를 관리합니다. 5.4절에서 설명한 대로 활성 단어들의 하한 중 k번째로 큰 값을 골라야 하므로, 부분 정렬 회로가 필요합니다. k가 작으면(16 이하) 정렬망 대신 k개 크기의 삽입형 레지스터 배열로 구현하는 편이 간단합니다.

구현은 단계적으로 확장하는 것을 권장합니다. 처음에는 θ를 외부에서 설정하는 고정값으로 두어 나머지 경로를 먼저 검증하고, 그다음 상위 몇 개 평면을 처리한 시점에 θ를 한 번만 계산해 고정하며, 마지막으로 매 평면마다 갱신하는 방식으로 넓혀 갑니다.

### 6.3 설계상 검토가 필요한 지점

설계를 진행하면서 판단이 필요한 사항이 네 가지 있습니다. 이들은 곧 본 프로젝트에서 실험으로 답할 항목이기도 합니다.

**(1) 자원 종류의 변화**

기준이 되는 일반적인 설계는 INT8 곱셈기를 사용하므로 FPGA의 DSP 블록을 소모합니다. 반면 본 설계는 조건부 덧셈만 사용하므로 DSP를 쓰지 않는 대신 LUT를 더 많이 사용합니다.

```
   기준 설계   : DSP 다수 사용,  LUT 적게 사용
   제안 설계   : DSP 미사용,     LUT 다수 사용
```

FPGA에서 DSP는 수량이 제한된 자원이고 LUT는 상대적으로 풍부합니다. 따라서 이 교환이 유리할 수도 불리할 수도 있으며, 실제 합성 결과로 확인해야 합니다.

**(2) 종단 시점의 불규칙성**

단어마다 종단 시점이 다르므로 파이프라인에 빈 구간이 생길 수 있습니다. 처리 방식은 몇 가지가 있습니다.

- 일괄 처리: 한 묶음 안에서 가장 늦게 끝나는 단어에 맞춤 (구현이 단순하나 절감 효과가 작음)
- 작업 압축: 중단된 자리에 다음 단어를 채워 넣음 (절감 효과가 크나 제어가 복잡함)
- 2단계 처리: 1단계에서 상위 평면만 전체 스캔한 뒤 생존한 단어만 2단계로 진행

**(3) θ를 언제 확정할 것인가**

5.4절에서 본 것처럼 θ는 활성 단어들의 하한에서 나옵니다. 그런데 평면을 적게 처리한 시점일수록 하한이 느슨하므로 θ가 낮게 잡히고, 그만큼 종단이 덜 일어납니다. 반대로 평면을 많이 처리한 뒤에 θ를 정하면 종단은 잘 되지만 이미 상당한 읽기가 발생한 뒤입니다.

```
   θ를 이르게 확정  ->  θ가 낮음  ->  종단 적음
   θ를 늦게 확정    ->  θ가 높음  ->  종단 많으나 이미 읽은 양이 많음
```

즉 θ를 몇 번째 평면에서 확정할지가 절감량을 좌우하는 파라미터가 되며, 매 평면마다 갱신하는 방식과 한 번만 정하는 방식 중 무엇이 유리한지도 함께 확인해야 합니다.

단어를 순차가 아닌 다른 순서로 처리하는 방식(최근 단어 우선, 이전 단계의 점수를 참고하는 방식 등)도 대안이 될 수 있습니다.

**(4) 손익분기점**

조기 종단은 공짜가 아닙니다. 제어 논리가 LUT를 소모하고, 판정 경로가 동작 주파수를 낮출 수 있으며, 불규칙한 종단이 파이프라인 효율을 떨어뜨립니다.

```
   비용 : 제어 논리 면적, 동작 주파수 저하, 파이프라인 빈 구간
   이득 : 연산 사이클 감소, 메모리 읽기 감소

   -> 어떤 조건에서 이득이 비용을 넘어서는가?
```

문장 길이 N, 상위 k의 크기, 종단 정책에 따라 답이 달라집니다. **이 경계를 찾는 것이 본 프로젝트의 결론에 해당합니다.**

이 목록이 알려주는 사실은 두 가지입니다.

첫째, **본 프로젝트가 다루는 문제와 접근 방식은 학술적으로 검증되어 있습니다.** 문제의 중요성이나 기법의 유효성을 따로 논증할 필요가 없습니다.

둘째, **이 분야는 이미 상당히 성숙해 있습니다.** 따라서 본 프로젝트는 새로운 구조를 제안하는 것을 목표로 하지 않습니다.

### 7.2 기존 연구가 다루지 않은 부분

표 7.1의 연구들은 모두 ASIC(주문형 반도체)을 전제로 설계되고, 시뮬레이션 또는 합성 결과로 평가되었습니다. 그런데 조기 종단 기법의 비용 구조는 구현 매체에 따라 크게 달라집니다.

```
   ASIC 에서
     - 곱셈기와 제어 논리 모두 게이트로 구현, 비용 구조가 연속적
     - 클럭 게이팅으로 중단된 경로의 전력을 세밀하게 차단 가능

   FPGA 에서
     - 곱셈은 DSP, 제어는 LUT로 서로 다른 자원을 사용 (교환 관계 발생)
     - 클럭 게이팅이 제한적이어서 전력 절감 양상이 다름
     - 불규칙한 제어가 배치·배선과 동작 주파수에 영향
```

즉 ASIC에서 확인된 이득이 FPGA에서 그대로 재현된다고 보기 어렵습니다. 그럼에도 이 기법을 FPGA에서 구현하고 자원·주파수·절감량을 함께 측정한 사례는 많지 않습니다.

### 7.3 본 프로젝트가 확인하려는 것

위 내용을 종합하면 본 프로젝트의 목표는 다음과 같이 정리됩니다.

> 조기 종단 기법을 FPGA에 구현하고, **이 기법이 실제로 이득이 되는 조건의 경계를 정량적으로 확인한다.**

구체적인 질문은 세 가지입니다.

1. 정확도 손실이 전혀 없는 조건에서 연산 사이클과 메모리 읽기는 얼마나 줄어드는가
2. 종단 기준을 공격적으로 잡았을 때 절감량과 정확도는 어떤 관계를 보이는가
3. 제어 회로가 소모하는 자원과 동작 주파수 저하를 감안하고도 이득이 남는 구간은 어디인가

이 방식의 장점은 결과가 어느 쪽으로 나오더라도 유의미한 결론이 된다는 점입니다. 이득이 크다면 기법의 FPGA 적용 가능성을 보인 것이고, 이득이 작거나 없다면 그 원인과 조건을 규명한 것이 됩니다.

## 8. 검증 방법과 진행 과정

### 8.1 비교 대상

같은 조건에서 네 가지 설계를 구현해 비교합니다.

**표 8.1 비교 대상 설계**

| 구분 | 설계 | 목적 |
|---|---|---|
| ① | 일반적인 병렬 INT8 곱셈 누산 구조 | 기준선 |
| ② | 비트평면 순차 처리, 조기 종단 없음 | 순차 처리 방식 자체의 비용 분리 |
| ③ | 비트평면 순차 처리 + 정확 모드 종단 | 정확도 손실이 없는 상태의 순수 이득 |
| ④ | 비트평면 순차 처리 + 근사 모드 종단 | 절감–정확도 관계 곡선 |

②와 ③의 비교가 특히 중요합니다. ②에서 순차 처리로 전환할 때 치르는 비용을 측정하고, ③에서 종단으로 얻는 이득이 그 비용을 넘어서는지 확인하는 구조입니다.

### 8.2 측정 지표

**표 8.2 측정 항목**

| 계층 | 도구 | 측정 내용 |
|---|---|---|
| 알고리즘 | numpy (PyTorch는 텐서 캡처용) | 평균 종단 시점, 상위 k 보존율, 언어 모델 품질 지표 |
| RTL 시뮬레이션 | Vivado Simulator | 연산 사이클 수, 메모리 읽기 횟수 |
| 논리 합성 | Vivado | LUT, FF, BRAM, DSP 사용량, 최대 동작 주파수 |
| 전력 | Vivado (스위칭 정보 기반) | 동적 전력 추정치 |

### 8.3 진행 과정

프로젝트는 네 단계로 진행합니다. 각 단계는 앞 단계의 결과를 입력으로 받습니다.

**1단계 — 알고리즘 수준 검증**  ✅ **완료**

실제 모델의 어텐션 점수에 비트평면 분해와 종단 판정을 소프트웨어로 재현합니다. 여기서 확인할 것은 "평균적으로 몇 개의 평면에서 종단되는가"와 "θ의 여유값을 키우면 정확도가 어떻게 변하는가"입니다.

이 단계의 결과가 이후 설계의 모든 파라미터를 결정합니다. 종단이 거의 일어나지 않는다면 설계를 다시 검토해야 하므로, 가장 먼저 수행합니다.

> **결과** — 저장소 `llm-et-attention` (numpy, 테스트 69개 통과). 평면별 생존 비율이
> `100 / 100 / 100 / 100 / 95 / 56 / 18 / 7 %` 로 나와 **평면 4부터 종단이 시작**됩니다.
> 정확 모드에서 상위 k 보존율은 1.0000 (무손실)이고 메모리 읽기는 26.6% 줄어듭니다.
>
> ⚠ **다만 이 수치는 합성 데이터 기준입니다.** 실제 Llama 3.2 1B 텐서로 다시 뽑아야
> 논문에 쓸 수 있습니다. 이것이 현재 최우선 과제입니다.

**2단계 — 기준 설계 구현**

비교 기준이 되는 일반적인 병렬 곱셈 누산 구조를 RTL로 작성하고 합성합니다. 이 단계에서 자원 사용량과 동작 주파수의 기준값을 확보합니다.

**3단계 — 제안 설계 구현**

비트평면 메모리, 부분 내적 유닛, 시프트 누산기를 먼저 구현해 종단 없는 순차 처리 구조(②)를 완성합니다. 이어서 조기 종단 제어기를 추가해 정확 모드(③)를 구현하고, 마지막으로 기준값 관리부를 확장해 근사 모드(④)를 구현합니다.

초기에는 θ를 고정값으로 두어 구조를 단순화하고, 동작이 확인된 뒤 상위 k 추적 방식으로 확장하는 순서를 권장합니다.

**4단계 — 측정 및 분석**

FPGA에 구현해 사이클 수와 메모리 읽기 횟수를 측정하고, 합성 보고서에서 자원과 주파수를, 스위칭 정보 기반 분석에서 전력 추정치를 얻습니다. 6.3절의 네 가지 검토 항목에 대한 실험을 이 단계에서 수행합니다.

### 8.4 최종 산출물

측정 결과는 두 개의 곡선으로 정리됩니다. 가로축은 θ에 더하는 여유값의 크기이고, 세로축은 각각 절감량과 정확도 손실입니다.

```
     절감량                          정확도 손실
       ^                               ^
       |      *---*---*                |             *
       |   *                           |         *
       | *                             |     *
       |*                              | *
       +------------------>            +------------------>
         θ 여유값 크기                     θ 여유값 크기

                    두 곡선을 겹쳐
              허용 가능한 손실 범위 안에서
              절감이 가장 큰 지점을 확인
```

**그림 8.1 최종 산출물의 형태**

여기에 표 8.1의 네 설계에 대한 자원·주파수·사이클·전력 비교표가 더해지면 프로젝트의 결과 보고가 완성됩니다.

## 9. 용어 정리

이 프로젝트에서 특별한 의미로 쓰이거나 혼동하기 쉬운 용어만 정리했습니다. 알파벳 순입니다.

| 용어 | 설명 |
|---|---|
| Arithmetic Intensity | 연산 강도. 메모리에서 1바이트를 읽을 때 수행하는 연산 횟수. 낮으면 메모리 병목 |
| Attention | 어텐션. 각 단어의 관련도를 계산해 가중 평균을 구하는 연산 |
| Bit-plane | 비트평면. 여러 값에서 같은 자리수의 비트만 모은 단위 |
| compute-bound / memory-bound | 연산 성능이 병목인 상태 / 메모리 대역폭이 병목인 상태 |
| Decode | 답변을 한 단어씩 생성하는 단계. 메모리 병목 |
| Early Termination | 조기 종단. 계산 도중 결과가 무의미함이 확정되면 남은 계산을 중단하는 기법 |
| exact / approx 모드 | 정확 모드(θ를 실제 값으로 사용, 손실 없음) / 근사 모드(θ를 높여 더 공격적으로 종단, 일부 손실 허용) |
| head_dim (d) | 어텐션 헤드 하나가 다루는 벡터의 차원. 일반적으로 64~128 |
| KV Cache | 이전 단어들의 K, V를 저장해 재사용하는 버퍼 |
| Masked-Sum | 비트가 1인 위치의 값만 골라 더하는 연산. 곱셈기를 대체 |
| MSB-first | 최상위 비트부터 순차적으로 계산하는 방식 |
| Prefill | 입력 프롬프트 전체를 한 번에 처리하는 단계. 연산 병목 |
| Q, K, V | Query, Key, Value. 어텐션의 세 입력 행렬 |
| Q+ / Q− | q 벡터 원소 중 양수인 것들의 합 / 음수인 것들의 합. 상한과 하한 계산에 사용 |
| R_m | 잔여 상한. 아직 읽지 않은 비트평면이 최대로 기여할 수 있는 값 |
| S_m | 상위 m개 평면까지 확정된 부분 점수 |
| L_m | 하한. 아직 읽지 않은 평면을 고려해도 점수가 이보다 낮을 수 없는 값 |
| Softmax | 여러 점수를 합이 1인 비율로 변환하는 함수 |
| Top-k | 상위 k개. 어텐션에서 비중이 큰 단어들을 선택하는 기준 |
| θ (theta) | 종단 판정의 기준값. 활성 단어들의 하한 중 k번째로 큰 값 |
| 분기 한정 | 상한과 하한을 함께 좁혀 가며 가능성 없는 후보를 제거하는 탐색 기법 |
