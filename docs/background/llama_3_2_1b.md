# 대상 모델 — Llama 3.2 1B

[architecture.md §1-3](../../architecture.md) 이 "계층 16, KV 헤드 8, 헤드 차원 64" 라고만
적고 넘어가는 부분의 배경이다. **그 숫자들이 어디서 왔고, 이 프로젝트에 무엇을 강제하는지**를 정리한다.

> 어텐션 자체가 어떻게 돌아가는지는 [transformer.md](transformer.md) 를 먼저 보면 된다.

---

## 1. 왜 이 모델인가

FPGA 에 올릴 것을 전제로 고른 모델이다. 기준은 세 가지였다.

| 기준 | 이유 |
|---|---|
| **작을 것** | KV 캐시가 온칩 메모리에 들어갈 수 있는 규모여야 실험이 성립한다 |
| **GQA 를 쓸 것** | 최신 모델의 표준. MHA 만 지원하면 결과의 수명이 짧다 |
| **공개 가중치** | 실제 Q/K 텐서를 떠서 합성 데이터를 대체할 수 있어야 한다 |

Llama 3.2 1B 는 셋을 다 만족하면서, head_dim 이 **64** 라 부분 내적의 누산 폭이
하드웨어에 편한 크기다. 8비트 값 64개의 조건부 합이므로 누산기 폭이 크게 필요하지 않다.

---

## 2. 스펙

출처는 `config.json` 이다. 저장소의 [config/model.yaml](../../config/model.yaml) 이 같은 값을 고정한다.

| 항목 | 값 |
|---|---|
| 파라미터 수 | 1.23 B |
| 계층 수 | **16** |
| hidden size | 2,048 |
| Q 헤드 수 | 32 |
| **KV 헤드 수** | **8** (GQA) |
| **head_dim** | **64** |
| FFN 중간 차원 | 8,192 |
| 어휘 크기 | 128,256 |
| 최대 문맥 | 131,072 (128K) |
| 위치 인코딩 | RoPE (θ = 500,000) |
| 정규화 · 활성 | RMSNorm · SiLU (SwiGLU) |
| 임베딩 공유 | 예 (tied) |

### 숫자들의 관계

```
hidden size 2048 = Q 헤드 32 × head_dim 64
GQA 그룹 크기    = Q 헤드 32 ÷ KV 헤드 8 = 4
                   → Q 헤드 4개가 K, V 한 벌을 공유한다
```

**KV 헤드가 8인 것이 이 프로젝트에 직접 영향을 준다.** MHA 였다면 K 를 32벌 들고 있어야 하지만,
GQA 덕에 8벌이면 된다. 저장할 비트평면 양이 4분의 1이다.

## 3. 모델 성능 — 무엇을 얼마나 하는가

Instruct 판 기준 공개 벤치마크다.

| 벤치마크 | 점수 | 무엇을 보는가 |
|---|---|---|
| MMLU (5-shot) | 49.3 | 57개 분야 객관식 지식 |
| ARC-Challenge | 59.4 | 초등·중등 과학 추론 |
| GSM8K (CoT) | 44.4 | 초등 수준 수학 문장제 |
| SQuAD | 49.2 | 독해 |
| HellaSwag | 41.2 | 상식적 문장 완성 |

**해석 주의.** MMLU 49.3 은 4지선다에서 찍기(25)보다는 확실히 낫지만
70B급(80대)과는 거리가 멀다. **1B 는 "실용 하한선"에 가까운 모델**이다.
온디바이스·엣지 배치를 노린 크기이고, 이 프로젝트가 FPGA 를 타겟으로 하는 것과 결이 맞는다.

### 이 모델이 만들어진 방식 — ★ 주의가 필요한 지점

Llama 3.2 1B 는 처음부터 1B 로 학습된 것이 아니다.

```
Llama 3.1 8B / 70B  ──(가지치기)──▶  1B 골격  ──(지식 증류)──▶  Llama 3.2 1B
                                     로짓을 교사 신호로 사용, 최대 9T 토큰
```

**가지치기와 증류를 거친 모델의 어텐션 분포가 처음부터 그 크기로 학습된 모델과
같다는 보장이 없다.** 이 프로젝트의 절감량은 전적으로 **어텐션 점수가 소수 토큰에
쏠려 있느냐**에 달려 있으므로, 이 사실은 결과 해석에 영향을 줄 수 있다.

지금은 합성 데이터(`target_logit_std: 5.0`, `sink_frac: 0.04`)로 그 쏠림을 흉내내고 있다.
**논문 수치는 반드시 실제 텐서로 다시 뽑아야 한다.**

```bash
python -m src.model_hooks --seq-len 512 --layer 8 --head 0
```

## 4. ★ KV 캐시 크기 — 이 프로젝트가 성립하는 이유

여기가 모델 스펙과 하드웨어가 만나는 지점이다.

```
KV 캐시 = 2 (K와 V) × 계층 16 × KV헤드 8 × head_dim 64 × T × 바이트
        = 16,384 × T × 바이트
```

| 길이 T | FP16 | INT8 |
|---|---|---|
| 512 | 16 MB | 8 MB |
| 2,048 | 64 MB | 32 MB |
| 131,072 (최대 문맥) | 4 GB | 2 GB |

**전체 모델의 KV 캐시는 온칩에 절대 들어가지 않는다.** 타겟 파트로 잡아 둔
`xc7z020` 의 BRAM 총량은 약 **4.9 Mb (630 KB)** 다. INT8 T=512 기준으로도 **13배 부족**하다.

그런데 이 프로젝트가 다루는 것은 전체가 아니라 **한 계층·한 헤드의 K** 뿐이다.

```
64 (head_dim) × 512 (T) × 1 바이트 = 32 KB = 256 Kb  →  BRAM36 약 8개
```

`xc7z020` 의 BRAM36 이 140개이므로 **여유가 충분하다.**
[config/hardware.yaml](../../config/hardware.yaml) 이 설계별 `bram36: 16` 으로 잡아 둔 추정치와도
자릿수가 맞는다(이중 버퍼링 등을 감안한 값).

| 범위 | INT8 크기 (T=512) | xc7z020 에 들어가는가 |
|---|---|---|
| 한 계층 · 한 헤드 · K only | 32 KB | ○ 여유 |
| 한 계층 · KV헤드 8 · K only | 256 KB | ○ (약 41%) |
| 전체 모델 K + V | 8 MB | **✕ 13배 초과** |

**이 표가 §1-3 의 "단일 계층·단일 헤드 수준에서 수행"을 정당화한다.**
범위를 좁힌 것이 게을러서가 아니라, 그 이상은 이 보드에 물리적으로 올라가지 않는다.

> ⚠ `fpga_part` 는 아직 `xc7z020clg400-1` 로 **예시** 상태다
> (hardware.yaml 주석: "실제 타겟으로 교체할 것"). 위 판정은 파트가 바뀌면 다시 해야 한다.

## 5. 양자화가 성능에 미치는 영향

이 프로젝트는 K 를 **INT8 비대칭 unsigned** 로 양자화한다([architecture.md §2](../../architecture.md)).

일반적으로 KV 캐시 INT8 양자화는 품질 손실이 거의 없다고 보고된다.
문제는 그 아래다 — INT4 이하로 내려가면 채널별(per-channel) 처리나 outlier 분리 같은
장치가 필요해진다. KIVI 가 K 를 채널 단위 비대칭으로 다루는 이유다.

**다만 작은 모델일수록 양자화에 민감하다.** 1B 는 여유(redundancy)가 적어
70B 에서 무해한 조작이 1B 에서는 드러날 수 있다. 이 프로젝트가 INT8 에 머무르는 것은
보수적인 선택이고, 그만큼 **비트평면이 8장**이라는 결과로 이어진다.

> 비트 수가 곧 평면 수다. INT4 로 내려가면 평면이 4장이 되어 순차 처리 사이클이 절반이 되지만,
> 동시에 **조기 종단으로 아낄 수 있는 여지도 줄어든다.** 8장 중 4장을 건너뛰는 것과
> 4장 중 2장을 건너뛰는 것은 절대량이 다르다.

## 6. 이 프로젝트가 재는 "성능"은 다르다

혼동하기 쉬운 지점이라 분명히 해 둔다. 위 §3 의 벤치마크 점수는 **모델의 성능**이고,
이 프로젝트가 재는 것은 **가속기가 그 성능을 얼마나 보존하는가**다.

| | 재는 것 | 어디서 |
|---|---|---|
| 모델 성능 | MMLU, GSM8K … | 위 §3 (Meta 공개값) |
| **이 프로젝트** | **상위 k 보존율**, 종단 시점, BRAM 읽기 수 | `outputs/` |

정확 모드(margin=0)에서는 상위 k 집합이 **비트 단위로 동일**하므로
모델 성능이 정의상 바뀌지 않는다. 근사 모드에서만 보존율이 1 아래로 떨어지고,
**그 경계를 찾는 것이 이 프로젝트의 결론**이다.

> 단, "상위 k 를 정확히 골랐다"와 "모델 성능이 유지된다"는 다른 명제다.
> vAttention (ICLR 2026) 은 **정확한 top-k 로도 full attention 을 항상 근사하지 못한다**는
> 것을 보인다. 자세한 것은 [related_work.md §5-1](../../related_work.md) 참조.
