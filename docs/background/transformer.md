# Transformer 와 Self-Attention — 배경지식

이 프로젝트가 가속하려는 연산이 **어디에서 나오는 것인지**를 정리한다.
하드웨어를 만드는 사람이 "왜 하필 Q·K^T 인가"에 답할 수 있을 만큼만 다루고,
학습(training)이나 모델 구조 전반은 다루지 않는다.

> 설계 자체는 [architecture.md](../../architecture.md) 를 보면 된다. 이 문서는 그 앞단이다.

---

## 1. 한 문장으로

> Self-Attention 은 **"지금 만들 단어가 앞의 어떤 단어를 봐야 하는가"** 를
> 매번 새로 계산하는 연산이다.

"본다"의 정도를 정하는 것이 **어텐션 점수**이고, 그 점수를 만드는 것이
`Q·K^T` 다. 이 프로젝트가 다루는 것이 정확히 이 부분이다.

---

## 2. Q, K, V — 세 벡터의 역할
입력 토큰 하나의 임베딩 `x`에 서로 다른 세 개의 학습 가능한 가중치 행렬(W_Q, W_K, W_V)을 곱해 세 가지 벡터를 만든다.
```
Q = x · W_Q      Query   — "나는 무엇을 찾고 있는가"
K = x · W_K      Key     — "나는 무엇을 제공하는가"
V = x · W_V      Value   — "선택되면 내가 넘길 내용"
```


| | 역할 |
|---|---|
| **Q** | 검색어 |
| **K** | 책 제목 (검색어와 얼마나 맞는지 판정용) |
| **V** | 책 내용 (실제로 가져갈 것) |

Q 와 K 를 맞춰 보아 **얼마나 관련 있는지**를 정하고, 그 비율대로 V 를 섞는다.
Query와 Key의 일치도가 높을 때 최종적으로 전달되는 실제 의미 데이터가 V이다.

---

### 3. 계산은 네 단계다

| 단계 | 수식 / 내용 | 비고 |
| :--- | :--- | :--- |
| **① 점수** | $S = \frac{Q K^T}{\sqrt{d}}$ | $\leftarrow$ **★ 이 프로젝트의 범위** |
| **② 마스킹** | 미래 토큰 가림 (causal) | 인과적(단방향) 마스킹과 대비되는 양방향 참조 방식에 대해서는 BERT 모델을 참고하시기 바랍니다.|
| **③ 정규화** | $A = \text{softmax}(S)$ | |
| **④ 가중합** | $O = A V$ | |

> $d$는 head 차원(이 프로젝트에서는 64)이고, $\sqrt{d}$로 나누는 것은 차원이 커질수록 내적 값이 커져 $\text{softmax}$가 한쪽으로 쏠리는 것을 막기 위한 것이다.

---

### 왜 ①만 다루는가

**①에서만 "필요 없는 것을 미리 알아낼" 여지가 있기 때문이다.**

* **③ softmax**는 지수함수라 모든 점수가 다 나와야 분모를 만들 수 있다.
* **④ 가중합**은 이미 정해진 비율대로 더하는 것이라 건너뛸 대상이 없다.
* 반면 **①은 점수가 작을 것이 확실한 토큰을 계산 도중에 알아낼 수 있다.**

그리고 $\text{softmax}$는 지수함수라서 점수가 조금만 낮아도 가중치가 급격히 0에 가까워진다. 그래서 상위 몇 개 토큰이 출력의 대부분을 결정하고, 나머지는 계산해도 거의 버려진다. 이 편중이 조기 종단이 성립하는 근거다.

---

## 4. Multi-Head 와 GQA
- 헤드(Head)는 고차원 잠재 공간을 서로 다른 저차원 부분공간으로 선형 사영하여, 다양한 관점에서의 상호작용 패턴을 포착하는 독립적인 어텐션 연산 단위입니다.
- 문장: "어제 만난 그 사람은 정말 친절했다."
- 1번 헤드 (문법 전문가): "주어('그 사람')와 서술어('친절했다')의 호응 관계"에 집중
- 2번 헤드 (문맥/지시 전문가): "'그 사람'이 앞에서 누구를 가리키는지"에 집중
- 3번 헤드 (감정/수식 전문가): "'정말'이라는 부사가 '친절했다'를 꾸며주는 관계"에 집중
  
어텐션은 한 번만 하지 않고 **여러 head 로 나누어 병렬로** 수행한 뒤 다시 합친다.
head 마다 다른 관계(문법, 지시 대상, 거리 등)를 잡으라는 의도다.

최근 모델은 Q 는 head 마다 따로 두되 **K 와 V 는 여러 head 가 공유**한다.
KV 캐시 용량을 줄이기 위한 것이다.

| 방식 | K, V head 수 |
|---|---|
| MHA (Multi-Head Attention) | Q 와 동일 |
| **GQA (Grouped-Query Attention)** | Q 보다 적음 — 그룹 단위 공유 |
| MQA (Multi-Query Attention) | 1개 |

> **Llama 3.2 1B** 은 GQA 를 쓴다. 계층 16, **KV head 8**, head 차원 64.
> 이 프로젝트는 그중 **단일 계층·단일 head** 를 대상으로 검증하고
> 나머지는 해석적으로 추정한다.

## 5. ★ Prefill 과 Decode — 이 프로젝트에서 가장 중요한 구분

LLM 추론은 성격이 완전히 다른 두 단계로 나뉜다.

### Prefill — 프롬프트를 한꺼번에 처리

입력 프롬프트 N 개 토큰의 K, V 를 **한 번에** 계산해 캐시에 넣는다.
행렬 × 행렬 연산이라 **연산량이 병목**이다.

### Decode — 한 토큰씩 생성

새 토큰 하나를 만들 때마다,

```
새 토큰의 Q  (1개)   ×   캐시에 쌓인 모든 K  (N개)
```

즉 **벡터 × 행렬**이다. 연산량은 작은데 **읽어와야 할 K 가 많다.**
그래서 병목이 연산이 아니라 **메모리 대역폭**으로 바뀐다.

| | Prefill | Decode |
|---|---|---|
| 처리 단위 | 프롬프트 전체 일괄 | 한 토큰씩 |
| 연산 형태 | 행렬 × 행렬 | 벡터 × 행렬 |
| K, V 쓰기 | N건 | **1건** |
| K, V 읽기 | — | **N건** |
| 병목 | 연산 | **메모리 대역폭** |

### 흔한 오해 하나

문헌에서 *"어텐션은 가중치가 매번 바뀌므로 메모리 중심 가속기에 부적합하다"* 는
서술을 종종 본다. **이는 Prefill 이야기다.**

Decode 에서 토큰 t 의 K 는 t 단계에 **한 번 저장된 뒤 이후 모든 단계에서 읽힌다.**
전체 길이 T 일 때 평균 재사용이 T/2 회이고, T=2048 이면 한 번 쓰고 약 1,000번 읽는다.
저장 비용은 충분히 상쇄된다.

**이 프로젝트는 Decode 만 대상으로 한다.** 위 구분이 프로젝트 전체의 전제다.

### 6. KV 캐시 — 왜 저장하는가

Decode 단계에서 토큰을 하나 만들 때마다 앞서 나온 모든 토큰의 $K, V$가 필요하다. 매번 처음부터 다시 계산하면 전체 연산량이 시퀀스 길이의 제곱인 $\mathcal{O}(T^2)$에 비례하여 낭비되므로, 한 번 계산한 $K, V$를 메모리에 저장(캐싱)해 둔다.

#### 문제는 크기다

KV 캐시의 전체 메모리 사용량은 다음 수식으로 결정된다.

$$\text{KV Cache Size} = 2 \times L \times H_{KV} \times d \times T \times B_{\text{elem}}$$

* $2$: $K$와 $V$ 두 개의 텐서
* $L$: 모델의 계층 수 (Layers)
* $H_{KV}$: $KV$ 헤드 수 (GQA/MQA 적용 시 $Q$ 헤드보다 적음)
* $d$: 헤드 차원 (Head Dimension)
* $T$: 현재까지 생성된 전체 시퀀스 길이 (Tokens)
* $B_{\text{elem}}$: 원소당 바이트 수 (예: FP16은 $2\text{ bytes}$, INT8은 $1\text{ byte}$)

캐시 크기는 문장 길이 $T$에 비례하여 선형적인 $\mathcal{O}(T)$ 크기로 계속 증가하므로 메모리 병목을 해결하기 위한 여러 기법이 사용된다.

---

| 접근 방식 | 동작 원리 | 특징 |
| :--- | :--- | :--- |
| **양자화 (Quantization)** | FP16 대신 INT8 / INT4로 표현 정밀도 축소 | 메모리 점유량 감소 (본 프로젝트는 INT8) |
| **가지치기 (Pruning)** | 중요도가 낮은 토큰의 $K, V$를 캐시에서 영구 삭제 | 토큰 단위 정보 손실 발생 |
| **조기 종단 (Early Termination)** | 캐시를 버리지 않고 **하위 비트평면 읽기만 생략** | **★ 본 프로젝트의 방식: 원본 무손실 보존** |

> **조기 종단의 차별점:** 데이터를 영구 삭제(Pruning)하거나 비가역적으로 깎아내는 방식과 달리, **저장된 $K, V$ 원본을 손상시키지 않고** 내적 기여도가 낮은 하위 비트의 메모리 읽기(Load) 트래픽만 동적으로 줄인다.

---

| :--- | :--- | :--- |

## 7. 이 프로젝트로 이어지는 지점

여기까지가 배경이고, 이 프로젝트는 다음 관찰에서 출발한다.

1. Decode 에서 병목은 **K 를 읽어오는 것**이다 (§5)
2. softmax 때문에 **상위 몇 개 토큰만 출력에 기여**한다 (§3)
3. 그렇다면 **상위에 못 들 토큰의 K 는 끝까지 읽을 필요가 없다**

3번을 하려면 "이 토큰은 상위에 못 든다"를 **다 읽기 전에** 알아야 한다.
그 방법이 상위 비트부터 계산하면서 점수의 가능 범위를 좁혀 가는 것이고,
자세한 내용은 [architecture.md §3](../../architecture.md) 에 있다.
